# KPassword 1.7.0 — Secrets Bridge universal

O Secrets Bridge no Linux passa a oferecer um único servidor MCP e gateway de
inferência em `127.0.0.1:8765`, iniciado e encerrado com a sessão da ponte.
As chaves dos provedores continuam no backend do KPassword. A criptografia e o
formato dos cofres, os backups e a chave pública do updater são preservados.

- MCP Streamable HTTP com a ferramenta `api_request`; adaptador stdio genérico
  para clientes sem autenticação HTTP dinâmica, incluído no RPM.
- Gateway com Chat Completions, Responses e Anthropic Messages, em JSON ou SSE
  nativos do provedor. Não há tradução automática de protocolos.
- Tokens temporários provisionados pelo socket privado, vinculados à identidade
  de processo observada no Linux. Tokens e sessões diferentes têm permissões
  isoladas; nomes declarados pelo cliente não substituem essa identidade.
- Aprovação única ou durante a sessão do aplicativo para a mesma credencial,
  operação e modelo. Removida a quantidade manual de chamadas do popup;
  limites automáticos de concorrência, chamadas e saída continuam aplicados.
- Host/Origin restritos, mensagens de erro filtradas, revogação central e
  encerramento do listener HTTP ao encerrar ou expirar a ponte.

## Instalação e atualização

Windows x64: `KPassword-Setup-v1.7.0.exe`. Updater assinado para instalações com a
chave pública introduzida na 1.5.0; versões anteriores exigem atualização manual.
O Bridge permanece indisponível no Windows até existir identidade e
provisionamento privado equivalentes. O gerenciador de senhas continua disponível.

Fedora 44 x86_64: `KPassword-1.7.0-1.x86_64.rpm`.

```bash
sudo dnf upgrade ./KPassword-1.7.0-1.x86_64.rpm
```

Faça backup criptografado antes de instalar. São fornecidos instaladores,
assinaturas verificadas localmente, `latest.json` e `SHA256SUMS.txt`. A assinatura
externa do RPM é Minisign, não GPG/RPM. A chave privada permanece local.

## Validação e limites

No Linux, passaram 91 testes Rust, 140 testes de frontend e 18 testes dos clientes
MCP/Unix/proxy. Treze chamadas reais usaram exclusivamente DeepSeek v4.1 Flash
(`deepseek-flash`), incluindo o cliente MCP HTTP nativo do Codex, os três protocolos
em JSON/SSE e chamadas concorrentes. O teste real de encerramento confirmou a
porta fechada e a recusa do token anterior. A CI deve validar o commit publicado
no Windows e Fedora e gerar os instaladores correspondentes.

A ponte é opcional e local. Ela não isola malware, depuradores ou injeção na
mesma conta do usuário. Uma chamada já enviada pode consumir recursos após
revogação. Limites locais de saída não representam um orçamento monetário.
MCP não troca o modelo principal de um agente. `/models`, Files API, entrada
HTTP chunked e conversão entre protocolos não são implementados. Não se
aguardou a expiração real de 48 horas; os limites de estado têm testes.

O aviso existente de chunks JavaScript acima de 500 KB permanece. Testes da CI
não substituem testes em todos os desktops, GPUs, WebKitGTK/WebView2, Windows
Hello, bandeja ou clipboard.

para configuração de clientes, escopos das permissões e limites de segurança.
